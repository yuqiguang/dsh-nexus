# Nexus for DSH

Nexus 是 [DeepSeek Harness（DSH）](https://github.com/deepseek-ai/deepseek-harness) 的第三方插件，把微信、飞书和企业微信连接到 DSH 的原生会话，并提供个人助理和编码工具设置。

DSH 负责模型调用、工具执行、会话历史、审批和恢复；Nexus 通过公开插件接口接入。目前插件版本为 **0.2.9**，精确匹配 **DSH 0.2.0-rc.2**。这是实验版本。

## 功能

- 渠道连接：微信扫码、飞书用户配对、企业微信机器人，绑定明确的消息所有者。
- 个人助理：人设、记忆、提醒、日历、待办和邮箱连接。
- 文件处理：接收附件、生成办公文件、按会话权限交付明确选择的文件。
- 编码工具：连接本机 Codex 或 Claude Code，管理工作目录、任务进度、审批和独立验证。
- 恢复：通过 DSH 原生存储保留会话和设置，按渠道记录恢复未完成的投递。

## 安装到桌面端

1. 从 [DSH 官网](https://deepseek.com/harness/) 安装桌面端，确认版本为 `0.2.0-rc.2`，并先完成模型配置。
2. 准备预构建的 `nexus-next-0.2.9.tgz`，或按下文从源码打包。包标识沿用 `nexus-next`。
3. 在 **插件 → 添加插件** 中填写安装包的本机绝对路径，安装完成后点击 **立即启用**。如果提示重启，从托盘完全退出后重新打开。
4. 打开 **设置 → 渠道连接 / 编码工具 / 助理**，按需配置。
5. 需要提醒功能时，在 **插件 → 官方** 启用 **自动化任务**（`@deepseek-ai/dsh-experimental-schedule-bundle`）。

Windows 安装应使用 Windows 本地路径，例如 `C:\Users\<user>\Downloads\nexus-next-0.2.9.tgz`。桌面端自带插件安装所需的 CLI 和 pnpm。

升级已有插件时，按 DSH 当前流程卸载旧插件，再添加新版安装包。卸载插件保留原生会话和渠道凭据。插件的 DSH 依赖由宿主提供，安装时应保持版本匹配。

## 配置渠道和工作目录

三个渠道默认关闭。首次启用需要完成各自的认证和用户绑定：

| 渠道 | 配置方式 |
| --- | --- |
| 微信 | 扫码并确认授权，绑定确认扫码的账号 |
| 飞书 | 填写 App ID 和 App Secret，在私聊发送配对码，再回到设置页确认绑定 |
| 企业微信 | 填写智能机器人的 Bot ID、Secret 和允许的用户 userid |

飞书应用需要启用机器人、长连接消息事件及相应权限，并对目标用户开放。

建议在各渠道的工作区字段填写独立的本机目录，例如 Windows 下的 `C:\Users\<user>\Documents\deepseek-harness\nexus`。使用编码工具时，检查其「允许的工作目录」包含目标项目。一般助理工作区宜放在代码仓库之外，避免加载仓库中的开发指令。

插件没有工作区覆盖配置时使用 `$DSH_HOME/nexus-workspace`，未设置 `DSH_HOME` 时为 `~/.dsh/nexus-workspace`。也可以在宿主 profile 的 `cordis.patch.yml` 设置插件默认目录，例如：

```yaml
- id: nexus-channels
  config:
    workspaceRoot: C:/Users/<user>/Documents/deepseek-harness/nexus
```

修改渠道工作目录后，下一条用户消息会在新目录建立会话。旧会话保留，工作文件不会自动搬迁。桌面端和源码运行的实例使用各自的数据与账号配置。

## 从源码运行和打包

需要 Node.js **22.20.0 或更新版本**。

```bash
npm ci
npm run build
npm test
npm start -- --no-open
```

源码启动会创建本项目独立的 `.nexus/` 数据目录及 `workspace/` 工作目录。通过终端显示的本机地址打开 Web 界面并配置模型。登录地址包含访问凭据，请保留在本机。

构建插件安装包：

```bash
npm run build
npm pack
```

安装包包含编译后的插件、客户端设置页和配置层。账号、会话、工作区、测试文件和内部文档不随安装包分发。`private: true` 用于防止误发布到 npm，不影响 GitHub 源码分发或本地安装包。

## 验证

```bash
npm run check
npm run build
npm test
npm run smoke
```

请串行执行构建和测试，并在运行集成检查前停止其他 DSH 实例。集成检查使用独立临时数据目录、本地模拟模型和渠道；插件安装阶段需要下载依赖。

Linux / WSL 是主要开发环境。仓库包含 Windows 的本地验证脚本，但本地模拟检查不能代表真实账号、模型任务或所有桌面平台均已验收。DSH 候选版本和原生沙箱行为仍可能变化。

## 数据与权限

渠道授权通过 DSH 原生凭据服务保存，界面只返回脱敏配置。远程消息必须匹配已绑定用户；审批回复受所属会话约束。工作区路径不等于对整个宿主文件系统的授权。

Codex、Claude Code 和各渠道平台需要各自可用的账号与服务。标准模式中的命令审批不等同于操作系统隔离；严格模式依赖平台上的原生沙箱支持。桌面安装不支持 Nexus 的整体数据导入。

请勿将 `.nexus/`、`.dsh/`、真实环境变量文件、认证地址或工作区中的私人文件提交到仓库。

## 第三方组件

本项目使用 DSH、飞书 SDK、企业微信 SDK 等第三方组件，其许可证和服务条款分别适用。Claude Agent SDK 按其发布包声明的条款使用；项目许可证不会重新授权该 SDK 或相关服务。安装包不包含 DSH、React 或 Claude Agent SDK 的实现。

报告问题时，请提供插件和 DSH 版本、操作系统、脱敏后的错误信息以及可复现步骤。
